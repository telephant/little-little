# T-01 Spike: SQLCipher + sqlite-vec build proof

Implements: AC-2 (mechanics)     Components: C-5
Depends on: — (first task; requires Rust toolchain — install via rustup if missing)
Context to read: docs/adr/0001-sqlcipher-via-rusqlite.md, docs/adr/0002-sqlite-vec-static-link.md, design-detail.md §Schema

Files to create/touch: `spikes/sqlcipher-vec/` (throwaway cargo bin, kept in repo for reference)

Goal: prove, in one tiny binary, that rusqlite with `bundled-sqlcipher-vendored-openssl` plus the `sqlite-vec` crate (registered via `sqlite3_auto_extension` once per process) can: create a keyed DB, create a `vec0` virtual table, insert and KNN-query vectors, reopen with the right key, fail with the wrong key.

Tests to turn green (asserts inside the spike's `cargo test`):
  TC-2 Encrypted at rest: Given DB with one row; When opened with stock SQLite (rusqlite without key, or `sqlite3` CLI); Then open/read fails (NOTADB).
  Spike-only assert: vec0 KNN query returns inserted vector with distance 0; wrong `PRAGMA key` fails the sqlite_master probe.

Done when: `cargo test` green in the spike; versions that worked (rusqlite, sqlite-vec) pinned and recorded at the bottom of this file and in design-detail.md if they differ from the design.
Out of scope: any app code, Tauri, migrations, chunking.
