# T-07 Memory engine: chunker, background embed worker, retrieval

Implements: AC-4, AC-5, AC-8, AC-16 (behavior)     Components: C-6
Depends on: T-03, T-05, T-06
Context to read: design.md C-6 + F-3/F-6 + Tricky parts, design-detail.md §Chunking + §Retrieval + §Background embed worker

Files to create/touch: `src-tauri/src/memory/` (`chunker.rs`, `worker.rs`, `retrieval.rs`), fixture file `src-tauri/tests/fixtures/entries.json`

Notes: chunker = blank-line paragraphs merged to ~1000 chars, hard-split >1500 on sentence boundary (provisional). Worker: single tokio task spawned on unlock; triggers = startup scan + save notify; idles while `embed_model` unset; transaction per entry (delete old chunks+vectors, insert new, status ok); transient Ollama errors keep `pending` with backoff (max 60s), permanent (model missing) set `failed`. Retrieval per design-detail SQL: exclude current entry, exclude `no_cloud` when `:cloud=1`, dedupe to best chunk per entry, top-3 entries, query vector = mean of the entry's chunk vectors.

  TC-5 Embed on save: Given models selected, fake embedder; When entry saved and worker runs; Then chunks rows + vec_chunks rows exist linked to entry, embed_status=ok.
  TC-6 Crash recovery: Given entry stuck pending (status pending, no vectors); When app restarts (startup scan); Then worker re-embeds it to ok.
  TC-10 Edit re-embed: Given embedded entry; When body edited and worker runs; Then vec_chunks contains vectors only for new chunk ids; old chunk ids gone.
  TC-11 Delete cleanup: Given embedded entry with a reflection; When entry deleted; Then its chunks, vec_chunks rows and ai_responses rows are gone (no orphans).
  TC-18 Selection gate: Given fresh journal, no models chosen; When entry saved; Then no embed/chat call occurs; When models chosen; Then pending entries embed. (panel-invite half asserted in T-09)
  TC-19 (finish): worker re-embeds after model change set all pending in T-05.
