# T-20 Settings clarity: plain words + provider cascade

Implements: verify finding V2-2 (AC-29 clarity). Components: C-3, C-13, C-14
Depends on: T-19 (done)
Context to read: src/screens/Settings.tsx, src/screens/Onboarding.tsx, src/components/StatusChips.tsx, docs/adr/0004-mood-provider.md

Why: the user's interactive pass (2026-11-05) flagged two confusions T-19 didn't cover: (a) jargon — "Embedding model", "Index dimension 768", chips saying "embeddings ready (…, 768d)" / "chat ready" mean nothing to a journal user; (b) cloud-vs-local — with Cloud selected, the local model pickers sit there unexplained, though they still matter (memory is always on-device; private entries use the local model per ADR-0004).

Decisions (user-directed):
- User-facing term for the embed model is **"Memory model"** ("Memory" is already the app's word — onboarding step 1, AI panel memories). "embedding"/"dimension" disappear from all user-facing copy; the stored keys, ipc params and Rust types keep their names (same boundary as T-19).
- **Cascade (user's design):** the Reflection model picker renders only when the provider is On-device. Under Cloud it is replaced by a note (no selection list) saying Claude writes reflections/moods/answers and naming the on-device model that still serves private entries — or warning when none is chosen.
- The Memory model picker always renders (memory is always on-device), with a hint saying so and keeping the re-index warning in plain words.
